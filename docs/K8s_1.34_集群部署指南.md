# Kubernetes 1.34 集群部署指南（GPU 就绪）

> 基于 kubeadm + containerd 从零部署 K8s 1.34 生产集群，包含 Helm 安装，满足 GPU 调度前置要求
>
> 撰写人：孟希東

---

## 集群规划

| 角色 | 主机名 | IP | 最低配置 |
|------|--------|-----|----------|
| Control Plane | k8s-master | 10.0.0.10 | 2 vCPU / 4 GB RAM / 50 GB |
| Worker (GPU) | k8s-gpu-01 | 10.0.0.21 | 4 vCPU / 16 GB RAM / 100 GB + NVIDIA GPU |
| Worker (GPU) | k8s-gpu-02 | 10.0.0.22 | 4 vCPU / 16 GB RAM / 100 GB + NVIDIA GPU |

- OS：Ubuntu 22.04 / 24.04 LTS（所有 GPU 节点必须相同版本）
- 容器运行时：containerd
- CNI：Calico
- Pod CIDR：`192.168.0.0/16`

## Phase 1 · 所有节点基础准备

> 以下步骤在**所有节点**（Master + Worker）上执行

### 1.1 设置主机名和 hosts

```bash
# 各节点分别执行
sudo hostnamectl set-hostname k8s-master   # 或 k8s-gpu-01 / k8s-gpu-02

# 所有节点添加 hosts
cat <<EOF | sudo tee -a /etc/hosts
10.0.0.10  k8s-master
10.0.0.21  k8s-gpu-01
10.0.0.22  k8s-gpu-02
EOF
```

### 1.2 关闭 Swap（必须）

```bash
sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

# 验证
free -h   # Swap 行应全为 0
```

### 1.3 加载内核模块

```bash
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

# 验证
lsmod | grep br_netfilter
lsmod | grep overlay
```

### 1.4 配置内核参数

```bash
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system

# 验证
sysctl net.bridge.bridge-nf-call-iptables
sysctl net.ipv4.ip_forward
```

### 1.5 关闭防火墙（或放通必要端口）

```bash
# 简单方式：关闭防火墙
sudo systemctl disable --now ufw        # Ubuntu
# sudo systemctl disable --now firewalld  # CentOS/RHEL

# 或放通必要端口（生产环境推荐）
# Master: 6443, 2379-2380, 10250-10252
# Worker: 10250, 30000-32767
```

## Phase 2 · 安装 containerd（所有节点）

### 2.1 安装 containerd

```bash
# 安装依赖
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

# 添加 Docker 官方 GPG 和仓库（containerd 在 Docker 仓库中）
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y containerd.io
```

### 2.2 配置 containerd（关键：启用 SystemdCgroup）

```bash
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml

# 启用 systemd cgroup 驱动（不配这个集群会初始化失败）
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

sudo systemctl restart containerd
sudo systemctl enable containerd

# 验证
sudo systemctl status containerd
```

> ⚠️ `SystemdCgroup = true` 是最常见的坑。不设置会导致 kubelet 和 containerd cgroup 驱动不一致，集群初始化失败。

## Phase 3 · 安装 kubeadm / kubelet / kubectl（所有节点）

### 3.1 添加 Kubernetes APT 仓库

```bash
# 安装依赖
sudo apt-get install -y apt-transport-https ca-certificates curl gpg

# 添加 K8s 1.34 仓库签名
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.34/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

# 添加 K8s 1.34 仓库
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.34/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list
```

### 3.2 安装指定版本

```bash
sudo apt-get update

# 查看可用版本
apt-cache madison kubeadm | head -5

# 安装 1.34 最新补丁版本
sudo apt-get install -y kubelet kubeadm kubectl

# 锁定版本（防止 apt upgrade 意外升级）
sudo apt-mark hold kubelet kubeadm kubectl

# 验证
kubeadm version
kubectl version --client
kubelet --version
```

### 3.3 启用 kubelet

```bash
sudo systemctl enable kubelet
```

> kubelet 此时会持续重启（正常），等待 kubeadm init 完成配置后才会稳定。

## Phase 4 · 初始化 Control Plane（仅 Master 节点）

### 4.1 执行 kubeadm init

```bash
sudo kubeadm init \
  --pod-network-cidr=192.168.0.0/16 \
  --kubernetes-version=v1.34.0 \
  --apiserver-advertise-address=10.0.0.10 \
  --control-plane-endpoint=10.0.0.10:6443
```

> `--pod-network-cidr=192.168.0.0/16` 是 Calico 默认网段，如用 Flannel 改为 `10.244.0.0/16`

### 4.2 配置 kubectl

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# 验证
kubectl get nodes
# 状态为 NotReady（正常，等安装 CNI）
```

### 4.3 保存 join 命令

kubeadm init 输出的最后几行包含 Worker 节点加入集群的命令，务必保存：

```
kubeadm join 10.0.0.10:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

> Token 24 小时后过期。如需重新生成：`kubeadm token create --print-join-command`

## Phase 5 · 安装 CNI 网络插件（仅 Master 节点）

### 5.1 安装 Calico（推荐）

```bash
# 安装 Tigera Operator
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.29.0/manifests/tigera-operator.yaml

# 安装 Calico 自定义资源
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.29.0/manifests/custom-resources.yaml
```

> 如果 pod CIDR 不是 `192.168.0.0/16`，需要先下载 custom-resources.yaml 修改 `cidr` 字段再 apply。

### 5.2 等待所有组件就绪

```bash
# 等待所有 Pod Running（约 2-3 分钟）
watch kubectl get pods -n calico-system

# 确认节点变为 Ready
kubectl get nodes
# NAME         STATUS   ROLES           AGE   VERSION
# k8s-master   Ready    control-plane   5m    v1.34.0
```

## Phase 6 · Worker 节点加入集群（GPU 节点）

### 6.1 在每个 Worker 节点执行 join

```bash
# 使用 Phase 4.3 保存的命令
sudo kubeadm join 10.0.0.10:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

### 6.2 在 Master 上验证

```bash
kubectl get nodes -o wide
# NAME         STATUS   ROLES           VERSION   OS-IMAGE
# k8s-master   Ready    control-plane   v1.34.0   Ubuntu 22.04
# k8s-gpu-01   Ready    <none>          v1.34.0   Ubuntu 22.04
# k8s-gpu-02   Ready    <none>          v1.34.0   Ubuntu 22.04
```

### 6.3 给 Worker 节点打标签（可选）

```bash
kubectl label node k8s-gpu-01 node-role.kubernetes.io/worker=worker
kubectl label node k8s-gpu-02 node-role.kubernetes.io/worker=worker

# GPU 节点标识
kubectl label node k8s-gpu-01 gpu=true
kubectl label node k8s-gpu-02 gpu=true
```

## Phase 7 · 安装 Helm

### 7.1 安装 Helm 3

```bash
# 方法一：官方脚本（推荐）
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

# 方法二：APT
curl https://baltocdn.com/helm/signing.asc | gpg --dearmor | sudo tee /usr/share/keyrings/helm.gpg > /dev/null
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/helm.gpg] https://baltocdn.com/helm/stable/debian/ all main" | sudo tee /etc/apt/sources.list.d/helm-stable-debian.list
sudo apt-get update
sudo apt-get install helm

# 验证
helm version
```

### 7.2 添加常用 Helm 仓库

```bash
helm repo add stable https://charts.helm.sh/stable
helm repo add nvidia https://helm.ngc.nvidia.com/nvidia
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo add grafana https://grafana.github.io/helm-charts
helm repo update

# 验证
helm repo list
```

## Phase 8 · 集群验证

### 8.1 基本健康检查

```bash
# 节点状态
kubectl get nodes -o wide

# 系统 Pod 状态
kubectl get pods -n kube-system
kubectl get pods -n calico-system

# 集群信息
kubectl cluster-info

# 组件健康
kubectl get --raw='/readyz?verbose'
```

### 8.2 部署测试应用

```bash
kubectl create deployment nginx-test --image=nginx --replicas=2
kubectl expose deployment nginx-test --port=80 --type=NodePort
kubectl get svc nginx-test

# 测试访问
curl http://10.0.0.21:<NodePort>

# 清理
kubectl delete deployment nginx-test
kubectl delete svc nginx-test
```

### 8.3 DNS 测试

```bash
kubectl run dns-test --rm -it --image=busybox -- nslookup kubernetes.default
# 看到 Address: 10.96.0.10 表示 CoreDNS 正常
```

## Phase 9 · GPU 就绪（后续步骤）

集群部署完成后，参考 [K8s GPU 调度与部署指南](K8s_GPU调度与部署指南.md) 完成以下步骤：

1. **安装 NVIDIA GPU Operator**（自动安装驱动 + Toolkit + Device Plugin）
2. **验证 GPU 资源注册**（`nvidia.com/gpu` 出现在节点 Allocatable）
3. **配置 GPU 共享策略**（Time-Slicing / MIG）
4. **部署 DCGM Exporter 监控**

快速预览：

```bash
# 安装 GPU Operator
helm install gpu-operator nvidia/gpu-operator -n gpu-operator --create-namespace --wait

# 验证 GPU 可用
kubectl get nodes -o json | jq '.items[] | {name:.metadata.name, gpu:.status.allocatable["nvidia.com/gpu"]}'

# 测试 GPU Pod
kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: gpu-test
spec:
  restartPolicy: OnFailure
  containers:
  - name: cuda
    image: nvcr.io/nvidia/k8s/cuda-sample:vectoradd-cuda12.5.0-ubuntu22.04
    resources:
      limits:
        nvidia.com/gpu: 1
EOF
kubectl logs gpu-test   # 看到 Test PASSED
```

## 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| kubeadm init 报 cgroup driver 不匹配 | containerd 未设 SystemdCgroup=true | 修改 config.toml 后重启 containerd |
| 节点一直 NotReady | CNI 未安装 | 安装 Calico |
| CoreDNS Pod 一直 Pending | CNI 未就绪 | 等 Calico Pod 全部 Running |
| join 命令提示 token 过期 | 默认 24h 过期 | `kubeadm token create --print-join-command` |
| 节点 join 后仍 NotReady | Worker 上 containerd/kubelet 配置问题 | 检查 Worker 的 containerd 和 kubelet 状态 |
| kubelet 不断重启 | init 未完成 | 正常现象，init 后稳定 |
